# 互动声音与BOOT静音 — 0.8.1

声音默认开启，固定80档输出音量，音频PCM峰值限制为6500（约满幅20%）。主页顶栏显示喇叭或静音图标。短按物理BOOT键切换声音，亮屏时显示“声音已开启/关闭”；开启时播放轻柔的双音确认，关闭时直接停止播放。

## 互动音效

| 操作或事件 | 声音 | 时长 |
|---|---|---|
| 单击摸头 | 短喵音 | 360ms |
| 三击挠肚皮 | 连续轻叫 | 420ms |
| 长按抱抱 | 低柔呼噜感音效 | 650ms |
| 左右滑逗猫 | 上扬喵音 | 260ms |
| 上滑击掌、成功换装 | 双音提示 | 180ms |
| 有效喂食 | 轻咀嚼声 | 480ms |
| 已吃饱、未达标的游戏结束 | 轻声回应 | 220ms |
| 双击或底部追星开局 | 三音上行 | 330ms |
| 正确命中星星 | 短提示音 | 65ms |
| 游戏或心愿奖励 | 四音旋律 | 520ms |
| 等级进化 | 五音旋律 | 700ms |
| 手动睡觉 / 叫醒 | 轻柔下行 / 上行 | 300 / 250ms |

均为项目原创合成音，不使用网络下载录音或麦克风。合成PCM为22050Hz、单声道、16位，播放时复制为左右相同的I2S双声道，带淡入淡出和幅度限制。喵音和呼噜属于合成音色，用户已在0.8.1板载扬声器上确认声音正常。可试听生产合成器导出的 [摸头](audio/head.wav)、[抱抱](audio/hug.wav)、[喂食](audio/feed.wav)、[追星](audio/play.wav)、[升级](audio/level.wav)。重新生成：`bash scripts/audio_preview.sh`。

动画有回应但摸摸成长还在冷却时，声音仍可正常播放。被进食或游戏忙碌状态拒绝的亲昵手势不发声；单/双/三击只在确认最终动作后播放，不叠加前面手势的声音。音效不改变饱食、成长、心愿或星星。

白天自主待机、夜间入睡、午休和自然起床保持安静。PWR熄屏、亮屏同样不播放声音。

0.8.0实机反馈音量过小或无声；0.8.1提高输出档位并把音色同时送到左右声道。用户随后确认“有声了”“声音正常，BOOT也能开关”，见[实机验收记录](hardware-0.8.1-flash-2026-10-30.md)。

## BOOT与保存

- BOOT为GPIO0，按下低电平。轮询20ms、稳定30ms去抖，在松手确认后切换一次，长按不连续切换。
- 上电时已经按住的BOOT，首次释放不切换声音。复位/上电时按住BOOT仍保留芯片进入下载模式的硬件用途。
- 开关偏好写入 `pet_nvs` 的独立 `audio/sound_on` 键；不改变宠物v3存档字段、CRC、双份记录或成长数据。重启继续使用上次成功保存的偏好。
- 持久化由音频任务完成，不在LVGL或按键轮询中直接等待Flash写入。保存失败会记录日志，保留上一次已提交值，不擦除NVS。
- 熄屏期间BOOT也能切换偏好，但不播放确认音、不读取触摸、不亮屏；只有PWR控制显示。

## 驱动与低功耗

使用ES8311、板载功放和扬声器。I2S为MCLK GPIO16、BCLK GPIO9、WS GPIO45、DOUT GPIO8，PA控制GPIO46；共用BSP现有I2C总线。引脚来自官方BSP3.0.0和[1.75C原理图](https://files.waveshare.com/wiki/ESP32-S3-Touch-AMOLED-1.75C/ESP32-S3-Touch-AMOLED-1.75C-schematic.pdf)，器件见[官方资源说明](https://docs.waveshare.com/ESP32-S3-Touch-AMOLED-1.75C)。

只分配I2S TX，不使用会同时启动RX的BSP双工便利接口，不初始化麦克风。音频在独立任务中分块合成和发送，界面仅提交请求。只有一个待播位置，新互动替代旧请求，避免连点积压。静音、熄屏会取消当前和排队音效；每次播放后关闭功放、DAC与I2S TX。

进入Light-sleep前等待音频停稳及设置提交。BOOT的GPIO低电平只唤醒CPU处理开关；按住期间低频检查释放，松开后恢复休眠，显示一直关闭。初始化或播放失败时标记音效不可用，显示提示，养成与触控继续运行。

## 验证边界

ASan/UBSan验证按键边界、抖动、长按、上电按住和计时回绕，以及14段PCM的非静音、峰值、直流偏移、首尾淡入淡出、整段/分块一致和越界保护。生产UI的真实LVGL指针测试验证手势、喂食、命中、奖励的音效请求；静音后玩法仍有效，熄屏BOOT不亮屏也不发声，音频失效可继续养成。

当前版本的扬声器实际出声、音量听感和BOOT基本开关已有用户实机确认；重启保持静音、按键边界和GPIO低功耗唤醒仍需专项验证。完整范围见[本版验证记录](verification.md)。
