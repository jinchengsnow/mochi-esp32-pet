# MOCHI 小猫养成游戏：完整玩法与逻辑

整理日期：2026-10-30。适用版本：**0.8.1**。设备：ESP32-S3-Touch-AMOLED-1.75C。

本文按当前 `main/` 源码整理已实现的玩法，统一说明操作、数值、成长、作息、声音、屏幕和存档之间的关系。历史版本文档中的“尚未烧录”等描述属于当时的验证状态；当前验证状态见文末。

## 1. 游戏目标与核心循环

玩家照顾一只名为 MOCHI 的小猫，通过触摸互动、喂食和短局小游戏获得成长与星星，完成陪伴心愿，逐渐看到小猫外形变化并购买装扮。

核心循环：**观察小猫 → 互动或喂食 → 玩追星星 → 获得成长和星星 → 完成心愿 → 升级形象和解锁装扮 → 继续陪伴。**

游戏采用轻松陪伴逻辑：饱食归零不会死亡，不扣成长，不会退化；没有签到中断、心愿过期或离线惩罚。当前成长路线固定为十级形象，没有性格分支、战斗或结局系统。

## 2. 界面与操作入口

| 位置或按键 | 作用 |
|---|---|
| 主页中心小猫区域 | 识别单击、双击、三击、长按和方向滑动 |
| 底部“喂食” | 尝试喂食 |
| 底部“追星” | 尝试开始追星星小游戏 |
| 底部“睡觉 / 叫醒” | 切换角色睡眠状态 |
| 顶部 MOCHI 名称 | 打开成长页，查看羁绊等级、星星、心愿和装扮 |
| 顶部“校时”或时间 | 打开日期、小时、分钟编辑页 |
| 顶部电池图标与文字 | 显示电量、充电与异常状态 |
| 顶部喇叭图标 | 显示声音状态，只读；通过 BOOT 切换 |
| 底部存档状态 | 显示“保存中 / 已保存 / 存档异常” |
| 短按物理 PWR | 熄屏或亮屏，在主页、成长页和小游戏中都有效 |
| 短按物理 BOOT | 开启或关闭声音，不切换屏幕 |

屏幕上没有熄屏按钮。触控手势从主页小猫区域开始，菜单和小游戏使用各自的按钮与目标。

## 3. 核心数值

| 数值 | 初始值与范围 | 获取或变化方式 | 用途 |
|---|---|---|---|
| 饱食度 | 初始 70，范围 0–100 | 随时间下降；喂食增加；游戏开局扣除 | 表达照顾需求，决定能否开始游戏和有效喂食 |
| 成长度（XP） | 初始 0，上限 600 | 自然成长、亲昵奖励、喂食、游戏与心愿 | 决定成长阶段、羁绊等级、形象和装扮购买资格 |
| 星星 | 初始 0，上限 9,999 | 达标游戏与完成心愿 | 购买永久装扮 |
| 陪伴心愿进度 | 初始三项均未完成 | 分别完成有效亲昵、喂食、达标游戏 | 集齐后自动发奖并开启下一轮 |
| 亲昵奖励冷却 | 初始 0，可立即领奖 | 领奖后设为 5 分钟，随运行时间减少 | 限制亲昵奖励频率 |
| 游戏冷却 | 初始 0，可立即开局 | 完成或退出后 60 秒 | 限制连续开局 |

另记录累计运行时间、有效喂食次数和已结算游戏次数。当前这些统计不提供额外数值加成。

## 4. 时间养成：亮屏与熄屏

| 设备状态 | 饱食自然下降 | 自然成长 | 完整一小时的基础变化 |
|---|---|---|---|
| 亮屏 | 每 5 分钟 −1 | 每 10 分钟 +1 XP | 饱食 −12，成长 +6 |
| 熄屏低功耗 | 每 30 分钟 −1 | 每 60 分钟 +1 XP | 饱食 −2，成长 +1 |
| 整机关机或完全断电 | 不补算 | 不补算 | 从最近成功存档恢复 |

亮屏时两种变化均为熄屏的 **6 倍**。表中一小时变化不含互动、喂食、游戏和心愿；达到数值边界后按边界截断。

- 倍率依据物理显示状态，角色正在睡觉、吃饭或处于菜单不改变倍率。
- 小猫在亮屏时睡觉，仍按亮屏速率；角色醒着但设备熄屏，按熄屏速率。
- 未满周期的进度跨屏幕切换和存档保留，不会因反复亮灭屏清零。
- 例如亮屏 4 分钟，再熄屏 6 分钟，恰好扣除 1 饱食。
- 饱食最低为 0；即使为 0，自然成长仍继续，成长不下降。
- 亲昵和游戏冷却在亮屏、熄屏期间均按真实经过时间减少，不使用 6 倍倍率；关机期间暂停。
- 修改日历时间只影响作息，不补发成长、不重复扣饱食，也不跳过奖励冷却。

## 5. 触控亲昵与玩耍

| 手势 | 动作 | 可见回应 | 奖励逻辑 |
|---|---|---|---|
| 单击 | 摸头 | 点头、闭眼微笑、爱心 | 共享亲昵奖励 |
| 双击 | 玩耍 | 进入追星星 | 使用小游戏的成本、条件与奖励，不发摸头奖励 |
| 三击 | 挠肚皮 | 扭动、大笑、摇尾、挥爪 | 共享亲昵奖励 |
| 长按约 650ms | 抱抱 | 靠近、抱起小爪、爱心 | 共享亲昵奖励 |
| 左滑或右滑 | 逗猫 | 朝对应方向看、抬爪追逗猫棒 | 共享亲昵奖励 |
| 上滑 | 击掌 | 举起肉垫小爪、星光 | 共享亲昵奖励 |

所有亲昵动作共享同一奖励计时器：首次可获得 **1 XP**，此后每累计运行 5 分钟最多再次获得一次。获得这次 XP 时，同时记入心愿的“摸摸我”项目。冷却中仍可获得动作和声音回应，但没有成长或心愿进度；换一种手势不会刷新冷却。

### 手势判定与防误触

- 单击、双击等待末次松手后约 320ms 才确认；三击在第三次松手时确认。
- 双击不会先执行摸头，三击不会先打开小游戏。
- 轻点要求单次按压不足 650ms，移动不超过 16 像素；长按触发一次抱抱，松手不再补发摸头。
- 左右或向上滑动至少 60 像素，且主方向明显，松手后触发。
- 下滑、小幅拖动、明显对角线、向外拖动再返回，不补发轻点动作。
- 四击及以上的快速连点按前三击触发一次挠肚皮，等待约 320ms 空隙后开始新一组。
- 喂食、睡觉、打开菜单或切换屏幕会取消待判定手势；触摸按下会立即打断自主待机。
- 进食或游戏中，普通亲昵操作不交叉结算；被拒绝的亲昵不发奖励或声音。

## 6. 喂食与饥饿反馈

| 条件 | 结果 |
|---|---|
| 饱食 ≤75，且没有正在吃饭或进行中的游戏 | 立即增加 25 饱食、4 XP，喂食次数 +1，记入心愿喂食项 |
| 饱食 >75 | 提示已经吃饱，给予开心和声音回应，不增加饱食、XP 或心愿进度 |
| 正在吃饭 | 不重复发奖，也不重启吃饭动画 |
| 游戏正在进行 | 不与本局交叉喂食 |

有效喂食在动作开始时一次性结算，吃饭动画持续约 **3.6 秒**，之后开心约 **2.4 秒**，再返回待机。普通亲昵开心反馈约 2.4 秒。

饱食 ≤25 时显示饥饿提示，眼神和摇尾减弱，饱食条使用提醒色。饥饿没有死亡、降级或成长惩罚，但低于 10 饱食时不能开新游戏。

## 7. 追星星小游戏

入口为双击小猫或底部“追星”。每局 **15 秒**，场上有五个固定目标位置，每次只亮起一个。

### 开始条件与成本

- 没有正在进行的游戏，没有正在吃饭。
- 游戏冷却归零，饱食至少为 10。
- 开局立即扣除 **5 饱食**；退出不会退还。
- 夜间或午休也可以主动开始游戏，触发临时清醒。

### 命中与结算

- 点击当前亮起的目标算命中，目标按 `(当前编号 + 2) % 5` 换位。
- 两次有效命中至少间隔 **180ms**，过密输入不重复计分。
- 点错目标会清空当前连击，累计命中保留；最佳连击用于结果展示。
- 奖励按累计命中次数决定，连击没有额外奖励倍率。
- 15 秒截止后统一结算一次，超时输入不计分。

| 总命中次数 | 本局成长 | 本局星星 | 心愿游戏项 |
|---|---|---|---|
| 0–4 | 0 | 0 | 不完成 |
| 5–9 | +3 XP | +2 | 完成 |
| ≥10 | +6 XP | +4 | 完成 |

如果本局同时完成整轮心愿，结果页显示的奖励会包含心愿奖励；接近数值上限时，显示实际增加量。

### 退出、熄屏与重启

- 主动退出中止本局，不发本局奖励，开始 60 秒冷却。
- 正常完成后同样冷却 60 秒，剩余秒数可查看。
- 熄屏不会暂停局内时间。若熄屏跨过截止时间，按熄屏前已经获得的命中数结算一次，之后冷却继续经过。
- 重启不续接未完成的一局，也不补发未结算奖励。开局时预留 75 秒计时（15 秒游戏 +60 秒冷却），读档恢复最近成功保存的剩余计时。

## 8. 陪伴心愿

每轮需要按任意顺序完成三项：

1. 一次获得 1 XP 奖励的有效亲昵，任一种亲昵手势都可以。
2. 一次有效喂食。
3. 一局至少命中 5 次的追星星。

三项集齐后立即自动奖励 **6 XP +5 星星**，清空三项，开始下一轮。每项每轮只记录一次，重复操作不会叠加该项进度；触发完成的动作只归属刚结束的一轮，不再次计入新一轮。

心愿进度会保存，没有每日刷新、签到要求或过期时间。亲昵冷却中只有动画，不能完成摸摸项；吃饱回应和主动退出游戏也不计入心愿。

首次完整循环示例：摸头 +1 XP，喂食 +4 XP，达标游戏 +3 或 +6 XP，心愿 +6 XP，总计 **14 或 17 XP、7 或 9 星星**，另有经过时间产生的自然成长。

## 9. 成长阶段、羁绊与十级形象

成长阶段和羁绊等级使用同一累计 XP，但门槛不同。

| 成长阶段 | 累计 XP | 作用 |
|---|---|---|
| 幼崽 | 0–19 | 初始阶段 |
| 少年 | 20–59 | 阶段外观变化，开放蝴蝶结购买 |
| 成年 | 60–600 | 阶段外观变化，开放皇冠购买 |

羁绊等级公式：`min(10, 1 + floor(XP / 60))`。20 XP 成为少年时仍为 Lv.1；60 XP 成为成年并升到 Lv.2；540 XP 达到 Lv.10，之后仍可累计到 600 XP。

| 羁绊等级 | 累计 XP | 小猫形象 | 主要特征 |
|---|---|---|---|
| Lv.1 | 0–59 | 奶团幼猫 | 奶油毛色、大圆脸、小身体、短尾 |
| Lv.2 | 60–119 | 蜜桃小猫 | 蜜桃毛色，身体与尾巴长大，第一道尾纹 |
| Lv.3 | 120–179 | 杏糖花猫 | 杏橘毛色、脸颊条纹、颊毛、两道尾纹 |
| Lv.4 | 180–239 | 蜜金橘猫 | 金橘毛色、更大的耳朵与身体、更多尾纹 |
| Lv.5 | 240–299 | 奶霜长毛 | 奶霜胸毛、双层颊毛、耳尖簇毛、蓬松尾尖 |
| Lv.6 | 300–359 | 月光银猫 | 银紫皮毛、月牙额纹、淡紫光弧 |
| Lv.7 | 360–419 | 星纹灵猫 | 紫色斑纹、星形额纹、星光配色 |
| Lv.8 | 420–479 | 星云长毛 | 蓬松颈毛、星云紫毛色、多层光弧 |
| Lv.9 | 480–539 | 极光灵猫 | 薄荷绿皮毛、银紫颈毛、月纹、极光光弧 |
| Lv.10 | 540–600 | 星耀守护猫 | 金色长毛、星形额纹与紫色星芯、守护星光 |

升级自动切换形象，播放约 2.8 秒进化星光并提示名称；游戏中升级，回到主页后展示反馈。读档按现有等级直接显示形象，不重复播放升级反馈。各级保留呼吸、眨眼、摇尾、进食、开心和睡眠动画。

形象变化不花星星，不重置装扮，不增加隐藏属性或小游戏加成。当前是固定进化路线，不因触摸偏好改变分支。

## 10. 装扮系统

| 装扮 | 购买门槛 | 首次价格 | 后续使用 |
|---|---|---|---|
| 不佩戴 | 无 | 免费 | 随时摘下 |
| 蝴蝶结 | 至少 20 XP（少年） | 8 星星 | 永久拥有，免费换上 |
| 皇冠 | 至少 60 XP（成年） | 16 星星 | 永久拥有，免费换上 |

购买同时装备，一次佩戴一件。已拥有的装扮不重复收费；星星或成长不足则保留现有装扮并提示条件。装扮随头部位置和尺寸变化，可与天生额纹同时显示，不影响养成效率。

## 11. 日历作息与手动睡眠

游戏使用北京时间 **UTC+8**。日期决定当天作息，时间在以下范围内小幅变化；同一天重启不会重新随机。

| 事件 | 当天时间范围 |
|---|---|
| 夜间入睡 | 21:45–22:15 |
| 早上起床 | 07:00–08:00 |
| 午休开始 | 13:00–13:15 |
| 午休结束 | 13:45–14:00 |

午休长度为 30–60 分钟。午夜继续保持夜间状态，起床使用新一天的计划；入睡边界开始休息，起床边界结束休息。

- 到睡眠时段，先完成当前进食、开心反馈或游戏，再进入睡眠；不会强制关闭成长页或结果页。
- 睡眠时可摸摸、喂食、开始游戏或点击“叫醒”，临时清醒 **10 分钟**；新的照顾操作可重新计算清醒期限，之后回到原睡眠时段。
- 点击“睡觉”可手动让角色休息；手动叫醒或照顾可以唤醒，夜间转白天、午休结束时也会恢复清醒。
- 亮屏白天不会因闲置 60 秒自动睡觉。
- 未校时不启用日历作息；尚未校时且已熄屏时，保留闲置 60 秒后的休息姿态。
- 熄屏仍更新作息，但小猫醒来不会点亮屏幕；角色睡眠不改变明暗养成倍率。

### 校时

首次点击顶部“校时”，设置日期、小时、分钟，保存后秒归零。之后点击时间可重校。编辑器的初始编译时间只是起点，需用户保存才视为有效时间。

当前没有联网校时。Light-sleep 期间芯片 RTC 继续走时；完全断电后需重新校准。明显向前或向后校时会清除依赖旧时钟的临时叫醒期限，并按新时间判断作息。临时叫醒期限与手动睡眠控制标记属于运行状态，不作为完整日历计划保存。

## 12. 白天自主待机动画

主页亮屏、角色清醒且空闲时，约等待 12–25 秒后播放一次约 5 秒的动作；进入空闲后的首次等待通常约 15 秒。动作伪随机选择，相邻两次不重复。

| 动作 | 表现 |
|---|---|
| 伸懒腰 | 闭眼、低头、伸前爪 |
| 洗脸 | 抬爪擦拭脸颊 |
| 玩毛线球 | 看着滚动毛线球并拨动 |
| 追看蝴蝶 | 转头、移动视线追看蝴蝶 |

触摸、菜单、喂食、睡觉、游戏和熄屏会中断待机。夜间、午休及这两个时段的临时叫醒期间不播放白天自主动作；未校时也可使用普通待机。

自主动作不增加 XP、星星或心愿，不额外消耗饱食；基础时间养成照常继续，也不发声音。

## 13. 声音与 BOOT 开关

声音默认开启，0.8.1 固定输出音量为 80 档；当前没有音量调节界面。音效为本地原创合成，播放时复制到左右声道。

| 事件 | 音效 |
|---|---|
| 摸头 / 逗猫 | 短喵音 / 上扬喵音 |
| 挠肚皮 / 抱抱 | 连续轻叫 / 呼噜感音效 |
| 击掌或成功换装 | 双音提示 |
| 喂食 / 已吃饱 | 咀嚼声 / 轻声回应 |
| 游戏开局 / 命中 | 三音上行 / 短提示音 |
| 游戏或心愿奖励 / 等级进化 | 奖励旋律 / 升级旋律 |
| 手动睡觉 / 叫醒 | 下行 / 上行轻音 |
| BOOT 开启声音 | 双音确认 |

- BOOT 在稳定松手后切换一次，长按不连续切换；上电时已经按住的首次释放不误切换。
- 关闭声音立即取消当前和待播音效，游戏与奖励仍正常进行；开关偏好独立保存。
- 亲昵奖励冷却中仍可发声；被忙碌状态拒绝的亲昵不发声。单、双、三击仅播放最终确认动作的声音。
- 新音效请求替代待播旧请求，避免连点积压；奖励或升级反馈可能替代普通回应。
- 自动待机、自动入睡与起床、PWR 亮灭屏保持安静。
- 熄屏立即停止音效并关闭播放通路；熄屏时 BOOT 可切换偏好，但不发确认音、不亮屏。
- 音频不可用时显示状态，养成和触控继续使用。

## 14. 电量、物理熄屏与低功耗

| 电池状态 | 显示 |
|---|---|
| 有效电量且未充电 | 电池图标与百分比，填充随电量变化 |
| 低于 10% 且未充电 | 提醒色与“请充电” |
| 实际充电中 | 闪电与“充电中”；低于 10% 仍使用提醒色 |
| 未检测到电池 | “未装电池”与叉号图标 |
| 读取失败或电量无效 | “电量 --”等未知状态，不伪装成 0% |

10% 本身不触发低电量标注，0% 是有效低电量。亮屏时约每 5 秒刷新一次电量。

短按 PWR 熄屏后进入保留内存的 **Light-sleep**：暂停界面和触摸，定时短暂唤醒检查 PWR、补算真实经过时间与作息。常态检查间隔约 500ms，因此 PWR 亮屏响应约半秒，保存期间可能稍长。

触摸不能亮屏、喂食、互动或命中星星；再次短按 PWR 恢复原页面，触摸等待已有手指松开后才接收新操作。BOOT 只处理声音偏好，不承担显示开关。PWR 长按保留硬件原有用途，不作为固件短按显示切换事件。

Light-sleep 保留游戏运行状态，数值与冷却继续经过；彻底关机停止运行，不补算离线时长。当前未测定整机实际休眠电流或续航，6 倍数值速率不代表 6 倍省电。

## 15. 状态衔接与优先级

| 场景 | 处理方式 |
|---|---|
| 亲昵后 | 开心约 2.4 秒，再回待机；到睡眠时段则再休息 |
| 有效喂食后 | 吃饭约 3.6 秒，开心约 2.4 秒，再回待机或按作息休息 |
| 吃饭时继续亲昵、喂食或开游戏 | 拒绝重复操作，避免重复结算；睡觉按钮可打断进食姿态 |
| 游戏进行中 | 普通照顾与装扮不能交叉结算；到睡觉时间先完成当前一局 |
| 自主待机时收到触摸 | 立即停止自主动作，再按手势规则回应 |
| PWR 熄屏 | 优先停声、关闭输入、保存并进入低功耗；局内时间继续经过 |
| BOOT 静音 | 停声，不改变玩法状态、数值与屏幕状态 |
| 打开成长或校时页 | 取消待判定手势和自主动作，基础时间养成继续 |

## 16. 存档、重启与升级

长期保存内容包括饱食、成长、星星、心愿三项进度、装扮所有权和当前装备、奖励与游戏冷却、自然变化未满周期的计时、累计运行与喂食/游戏统计，以及角色睡眠标志。声音偏好单独保存。

开心和进食动画进度、待判定触摸、小游戏当前目标/命中/连击、自主待机、临时清醒期限等不续存。角色睡眠标志恢复后仍会受到有效日历作息重新判断。

- 动作和重要数值变化请求保存，后台约 1 秒合并写入。
- 亮屏约每 30 秒保存累计计时；低功耗期间约每 5 分钟保存，进入和退出低功耗时也请求保存。
- 断电前等到“已保存”；突然断电可能回到最近一次成功记录。
- 使用独立 `pet_nvs` 分区，宠物两份记录交替保存，包含版本、CRC 和数值检查；异常存档不自动清空。
- 当前 v3 格式兼容读取 v1/v2，迁移保留原有进度；普通固件升级保留宠物分区。
- 新版写入 v3 后，0.4 及更早固件不能直接读取，回退需要先保留备份。

## 17. 当前实现与验证范围

0.8.1 已刷入设备，用户已确认“声音正常，BOOT也能开关”。当前规则有模型、手势、存档、作息、声音等软件测试及真实 LVGL 输入集成验证。

实际休眠电流、续航、长期稳定性、RTC 长期漂移、冷启动静音记忆以及熄屏 BOOT 唤醒边界，仍需专项实机验收。声音基本开关已通过，不代表上述项目均已完成。

当前没有接入六轴体感玩法、麦克风或语音识别、联网校时、离线时长补算、拖拽喂食、音量档位或成长分支。这些不计入本文已实现玩法。
